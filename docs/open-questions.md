| 15 | §5.3's row-count checksum had no declared row total to check against | §5.3 originally asked that `N` equal "the page footer's declared count … combined with rows-per-page". The real export's footer declares **pages**, not rows, and rows-per-page is an undeclared layout artefact | **Resolved (2026-07-28)**: user confirmed the spec clause was in error; §5.3 has been rewritten to require two independent checks — `Nr.` contiguous `1..N`, **and** every footer-declared page present. If an export format ever prints an explicit participant total, add it as a third check |
| 16 | Charting library for the §9 interactive dashboard | §9 left it open: "Chart.js/Recharts/Plotly — pick one during implementation" | **Resolved (M4)**: **Recharts**. Pure SVG, so it needs no `canvas` polyfill under jsdom the way Chart.js would, and it is declarative React rather than an imperative instance to manage in an effect. Bundled by Vite, so no runtime CDN fetch (§13). Mitigation for its one real weakness under jsdom is structural: every payload→series transform is a pure tested function in `frontend/src/statistics/series.ts`, and every chart is accompanied by the same data as a `<table>`, which most tests assert against and which also prints. See item 20 for how the charts themselves are exercised |
| 17 | Charts inside the §9 PDF: `cetz`/`cetz-plot` vs. native Typst drawing | §12 names `cetz` + `cetz-plot`, vendored into the image at build time (§13) | **Resolved (post-M4) — back to the spec's choice.** Initially deviated: bars were drawn with native Typst primitives behind one `bar-chart()` function, to avoid committing a third-party package tree ahead of §15.6. The user reviewed the output and rejected it — the hand-drawn bars ran left-to-right, inverting the axes, and looked poor. They also clarified the §13 constraint: it forbids ever **uploading** exam data, and a build-time download of a public package is fine. So `cetz` 0.3.4 + `cetz-plot` 0.1.1 are now fetched by `backend/scripts/vendor_typst_packages.py` (version- and SHA-256-pinned) into a gitignored tree, wired in through `typst-py`'s `package_path`, and the Dockerfile runs the same script at build time. Both packages are **LGPL-3.0** in an otherwise proprietary repo — hence downloaded rather than committed, with LICENSE files preserved in the image. Lesson worth keeping: the deviation was defensible on paper and still wrong in practice, because nobody looked at the rendered PDF until after it shipped |
| 18 | What §9's statistics mean while grading is still in progress | Not addressed by the spec, which only says §9 is "a live view over current data … useful while grading is still in progress" | **Decided (M4)**: a student who attended but is missing at least one exercise entry is counted as `incomplete` and left out of the grade distribution and the total-points histogram — their partial sum would otherwise render as a fake "nicht bestanden" — while their individually entered exercise points still count in that exercise's own histogram, where they are a complete fact. Pass and failure rates divide by `graded` (attended **and** complete), not by `attended`, or an in-progress exam would understate its failure rate. Both views must show the `incomplete` count prominently. Two refinements found while testing the seam: (a) a student recorded as **absent** whose points are still stored — a state `docs/api-contract.md` guarantees is reachable, since flipping `attended` to false deliberately keeps points so nobody re-transcribes an exam — is excluded from the per-exercise histograms too, because §7.4 makes those points play no part in any grade; a student whose attendance is merely *not yet recorded* still counts, since entering points before ticking attendance is an ordinary order to work in. (b) attended-and-complete students on an exam with **no grading schema yet** get their own `counts.awaiting_schema` bucket rather than falling into none, so the five buckets always partition `registered` — without it an instructor who configures the schema last watched students vanish from every count. Confirm the instructor reads all of this the same way once they use it on a real exam |
| 19 | Rounding of §9's derived numbers | Not specified | **Decided (M4)**: mean/median grade to 2 decimal places, rates to 1, both `ROUND_HALF_UP`, and **rounded once in `app/statistics.py`**, never in a renderer — §9's "one shared statistics module" requirement is defeated if the PDF and the dashboard round the same payload differently. For the same reason every rate travels as `numerator`/`denominator`/`percent` together so neither view divides, and histogram bin captions are formatted German-side in that module rather than twice in two renderers |

| 20 | Recharts renders nothing under jsdom, so chart components can be shipped untested | Not foreseen; `ResponsiveContainer` measures 0 without layout, and an animated `Bar` emits no `<rect>` on its first frame | **Resolved (M4)**: the test file installs a `ResizeObserver` stub that reports a real 800×400 box, and `charts.tsx` sets `isAnimationActive={false}` (also the better behaviour for a live view that re-fetches). Chart tests assert bar **heights**, not just element counts — a `<rect>` is emitted for a `dataKey` bound to a nonexistent field too, just flat, so counting elements alone proves nothing. Verified by mutating a `dataKey` and watching the suite fail. Note `npx tsc --noEmit` does not cover test files; `npm run build` (`tsc -b`) does — use the latter |

| 21 | Attendance input: two-state checkbox vs. preserving "not yet recorded" | Not in the spec. §4 makes `attended` nullable and §8.1 requires the export gate to distinguish "never recorded" from "did not appear" | **Decided (post-M4)**: a **radio pair** per student (anwesend / nicht anwesend), neither selected while `null`. The user rejected both a plain two-state checkbox (an untouched exam would read as "everyone absent" and pass the §8.1 gate with everyone "n.e.") and a tri-state checkbox cycling through indeterminate (two clicks to mark an absence). Radios cost exactly one click for either outcome and still leave the unrecorded state visibly distinct. A header "alle als anwesend" bulk action exists behind a confirmation dialog |
